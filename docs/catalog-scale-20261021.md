# 카탈로그 범위와 대표 후보 수

**대표 후보 목표 200개는 보장된 도킹 완료 수가 아닙니다.** 카탈로그에서 확보한 후보, 검색 필터를 통과한 후보, 도킹 계획에 포함된 후보, 실제 계산·자세 QC를 마친 후보, 최종 대표 후보는 서로 다른 집계입니다. 관측 리간드 재도킹은 신규 후보 도킹 수에 합치지 않습니다. 동일 조건의 저장 결과 재사용도 새 Vina 실행과 구분합니다.

## 짧은 조작 확인과 실제 연구 범위

README의 CRABP2–1CBS 첫 도킹 예제는 **대표 목표 3 / 카탈로그 상한 50 / 최대 0.5시간**의 작은 동작 확인입니다. 기본 연구 설정은 여전히 **대표 목표 200 / 카탈로그 상한 1,000 / 최대 2시간**입니다.

같은 원본 1CBS/A/REA 구조에서 더 넓게 확인하려면:

1. 기존 결과에서 설정을 덮어쓰지 말고 **다른 입력으로 새 연구** 또는 **새 연구 시작**으로 별도 연구를 만듭니다.
2. 단백질은 CRABP2 / 사람 / P29373를 확인하고 **후보 수·필터·최대 처리 시간 조정**에서 PDB ID `1CBS`, 단백질 사슬 `A`, 기준 리간드 코드 `REA`를 입력합니다. 결합 구조 모드는 README의 원본 1CBS 파일·관측 리간드 선택·검증된 SMILES 순서를 따릅니다.
3. **후보를 어디서 찾을까요? → 공통 카탈로그**를 선택합니다. **대표 후보 목표 200 / DB에서 평가할 최대 후보 수 1,000 / 최대 처리 시간 2시간**을 확인합니다. 구매 기록·구조 경보·독성·작용 방향 필터, 관측 원자 보존 및 자세 QC 기준은 유지합니다.
4. 기본 범위보다 넓힐 때는 DB 후보 상한을 최대 10,000까지 직접 설정할 수 있습니다. 대표 목표는 최대 1,000, 연구 시간은 최대 8시간입니다. 큰 값은 후보 수나 도킹 성공을 보장하지 않으며 시간·저장 공간이 더 필요합니다. 구조가 많은 로컬 카탈로그가 준비되어 있어야 합니다. 작은 starter 카탈로그에 숫자만 크게 넣는다고 원본 DB가 늘어나지 않습니다.
5. **새 연구 실행**은 한 번 누릅니다. 접수가 지연되면 실행 기록에서 먼저 확인합니다. 파란 **연구 진행 중** 표시와 현재 단계·처리 수를 확인하고, 화면을 이동한 뒤에도 **진행·결과 보기**에서 다시 엽니다. 대기는 실행 실패나 후보 0개를 뜻하지 않습니다.
6. 완료 후 요청 범위·실제 확보 수·후보 도킹·재도킹·최종 대표·보류 사유를 비교합니다. **전체 후보 표 보기**에서 미평가·대안·제외 행을 확인합니다.
7. **Excel · 전체 후보·개별 물질 탭 → 준비된 Excel 묶음 ZIP 저장**을 누르고 ZIP의 `review-0001.xlsx`를 엽니다. 큰 결과는 여러 `review-*.xlsx`로 나뉠 수 있으므로 ZIP 전체와 모든 workbook·JSON·자세 파일을 보존합니다.

공통 카탈로그의 상한은 현재 검색에서 가져올 최대 후보 수입니다. 전체 DB를 모두 평가했다는 뜻도, 무작위 표본이라는 뜻도 아닙니다. **기존 연구 모집단을 출처로 선택하면 원본 모집단 전체를 보존하는 별도 경로**를 사용하므로 같은 상한이 그 전체 행 수를 잘랐다고 해석하지 않습니다.

## 50개가 3개·2개가 된 실제 단계

| 최초 제외·보류 단계 | 단백질 예제 | 결합 구조 예제 |
|---|---:|---:|
| 확보한 카탈로그 후보 | 50 | 50 |
| 검색 필터에서 먼저 제외 | 6 | 6 |
| 검색 통과 후 추가 루틴 보류 | 40 | 42 |
| 앞 단계 통과 후 대조군과 같은 parent여서 추가 제외 | 1 | 0 |
| 후보 도킹 입장·완료·자세 QC 통과 | 3 | 2 |

이 표의 최초 제외 단계는 서로 겹치지 않습니다. 별도의 사유별 집계는 한 후보의 불명확한 입체화학·구조 경보 등이 동시에 나타날 수 있으므로 합산하면 안 됩니다. 동일한 50개에서 목표만 200으로 올려도 추가 적격 후보는 생기지 않습니다. 기존 결과의 `target_reached`는 목표 도달, `eligible_pool_exhausted`는 현재 조건에서 추가 계산할 후보가 없다는 뜻입니다.

검색 필터를 통과한 44개를 모두 도킹 가능한 후보로 읽으면 안 됩니다. 명시적 입체화학, 대조군 parent 중복, 구조 경보, 정확 구조의 예측·포즈 QC 등 후속 조건이 별도로 적용됩니다. 미기록·미평가를 0·안전·통과로 간주하지 않습니다.

과거 연구의 “대표 최대 200개”는 그 연구·조건의 저장 모집단에서 선정한 관측 수일 수 있습니다. 현재 새 연구의 신규 Vina 실행 수와 직접 비교하려면 요청 범위·모집단·QC·신규/재사용을 먼저 맞춰야 합니다. 계산·QC 통과는 실험적 결합·피부 효능·안전성의 입증이 아닙니다.

## 큰 묶음의 상세 자료 취득과 원시 QC 파일

기본 규모의 실제 점검에서 상위 1,000개 ID 검색은 성공했지만 상세 자료 취득이 실패한 사례를 확인했습니다. 이전 50개는 새 목록의 앞 50개와 정확히 같았습니다. 같은 1,000개 상세 요청을 재생하면 기존 120초 취득 한도에 도달했습니다. 이는 1,000개가 모두 QC에서 탈락했다는 뜻이 아닙니다.

상세 취득은 이제 50개씩 나누어 요청합니다. 전체 top-K 후보 수·순서·검색 필터·출처 지문·관측 원자 보존·도킹 QC는 유지하고, 각 전송의 기존 120초·64MiB 제한도 유지합니다. 모든 묶음의 출처와 ID 순서가 같아야 합칩니다. 전송 오류가 난 POST를 자동으로 재제출하지 않습니다. 운영망의 일시적인 연결 단절은 별도 문제이며 작은 묶음으로 모든 네트워크 장애가 해결되는 것은 아닙니다.

새 Excel 내보내기는 후보 JSON의 QC 지표뿐 아니라 명시적으로 연결된 원시 PoseBusters CAS 파일과 저장 도킹 재사용 출처 JSON도 ZIP에 보존합니다. 원문이 없거나 해시가 맞지 않으면 경고를 남기고 원래 관측을 보존합니다. 서버 경로를 따라 파일을 읽거나 과거 캐시를 재귀적으로 확장하지 않습니다. 기존 ZIP을 수정하지 않으므로 예전 내보내기의 원시 파일 포함 범위는 새 내보내기와 다를 수 있습니다.
