# SkinPipe

[English](README.md) · [브라우저 사용 순서](docs/browser.ko.md) · [설치·DB·모델 안내](docs/catalog.ko.md)

SkinPipe는 피부 연구용 화합물 스크리닝 플랫폼입니다. 화합물 이름·SMILES, 단백질 이름, 단백질–리간드 결합 구조 중 하나에서 시작합니다. 입력을 확인하고 분석한 뒤 후보 비교, 구조·피부·독성 평가 확인, Excel 내보내기까지 브라우저에서 진행합니다.

이 저장소는 소프트웨어와 설치 안내만 제공합니다. 연구 입력·분석 결과·화합물 DB·예측값·모델 가중치는 각 사용자의 별도 설치 폴더에 저장됩니다. 연구 이력과 사전 지정 표적은 빈 상태로 시작합니다.

## 한 번에 설치하고 실행하기

**Ubuntu 24.04 x86_64의 일반 사용자 계정**에서 실행합니다. sudo 권한, Python 3, 인터넷, **20 GiB 이상의 여유 공간**이 필요합니다. 시스템 패키지 설치 시 터미널에서 Ubuntu 비밀번호를 묻습니다.

Ubuntu 터미널에 아래 한 줄을 붙여 넣으세요.

```sh
python3 -c 'import urllib.request; exec(compile(urllib.request.urlopen("https://raw.githubusercontent.com/kangk1204/SkinPipe_public/main/install.py", timeout=30).read(), "SkinPipe installer", "exec"))'
```

공개 소스 → 앱·별도 ADMET 모델 환경 설치 → 공식 출처의 작은 화합물 목록 다운로드 → ADMET 계산 → 검색 인덱스 구축 → 앱 시작 순서로 진행합니다. 터미널에 **`SkinPipe: http://127.0.0.1:4317`** 이 나오면 브라우저에서 **http://127.0.0.1:4317** 을 여세요. 실행 터미널은 열어 두세요. 그 전에 나오는 **Installation prepared**는 설치 준비 완료를 뜻하며, 서버가 DB를 확인하는 동안 조금 더 기다릴 수 있습니다.

**최초 준비는 오래 걸립니다.** 모델·패키지를 처음 내려받고 ADMET과 검색 인덱스를 만들기 때문입니다. 터미널의 단계와 로그 위치로 진행 상황을 확인합니다. 기본값 `--device auto`는 NVIDIA GPU의 실제 계산을 검사해 사용하고, 사용할 수 없으면 CPU로 진행합니다. 도킹은 설치한 CPU Vina 엔진을 사용합니다. GPU 드라이버를 설치하거나 변경하지 않습니다.

기본 DB는 사용법을 익히기 위한 **작은 starter 목록**입니다. 전체 라이브러리는 검색 범위가 더 넓지만 **300 GiB 이상**의 공간이 필요하며 CPU 계산은 **수일 이상** 걸릴 수 있습니다. [출처·이용조건·전체 구축 방법](docs/catalog.ko.md)을 먼저 읽어 주세요. 이 저장소에서 미리 계산한 DB를 내려받는 방식이 아닙니다.

macOS·Windows는 Ubuntu 서버에 설치한 뒤 [SSH 터널로 접속](docs/catalog.ko.md#macoswindows의-브라우저에서-접속)합니다. 이 설치기는 macOS·Windows에 직접 설치하는 프로그램이 아닙니다.

## 화면을 보며 첫 연구 진행하기

아래는 **0.3.0rc1 starter 설치 환경에서 직접 촬영한 화면**입니다. 처음에는 단백질·도킹 설정이 필요 없는 **Nicotinamide**로 따라 해보세요. 이미지를 누르면 크게 볼 수 있습니다. DB 구성과 컴퓨터에 따라 개수·시간은 달라집니다.

### 1. 설치 준비 상태 확인

터미널에 **`SkinPipe: http://127.0.0.1:4317`** 이 나오면 **http://127.0.0.1:4317** 을 열고 오른쪽 위 **설치 상태**를 누릅니다. **PostgreSQL 연결됨**, 화합물 개수가 보이는지 확인하세요. ChatGPT는 연결하지 않아도 됩니다. **연구 화면으로**를 눌러 시작합니다.

![설치 상태: DB 연결, starter 카탈로그와 선택적 ChatGPT](docs/images/01-installation-ready.jpg)

### 2. 화합물 이름 입력

**화합물을 알고 있어요**를 선택합니다. 입력 방식은 **화합물 이름**으로 두고 `Nicotinamide`를 입력한 뒤 **입력 확인하기 →**를 누릅니다. 식별을 마칠 때까지 기다리세요. 아직 분석을 시작한 단계는 아닙니다.

**이름 조회가 시간 초과되면:** 아직 연구를 접수한 것이 아닙니다. **화합물을 알고 있어요 → 입력 방식 → SMILES 분자 구조 (선택)**으로 바꾸고, 이 Nicotinamide 예제의 정확한 구조 `NC(=O)c1cccnc1`을 넣어 **입력 확인하기 →**를 다시 누릅니다. 2D 구조를 확인한 뒤 계속합니다. 이름 조회 장애와 분자 구조 오류를 구분하며, 다른 물질은 그 물질의 확인된 SMILES가 있어야 이 경로를 사용할 수 있습니다.

![Nicotinamide 입력과 입력 확인하기 버튼](docs/images/02-compound-input.jpg)

### 3. 이름과 분자 구조 확인

**Nicotinamide**, **PubChem CID 936**, **2D 구조**를 확인합니다. 다른 분자라면 **← 입력 수정**, 맞으면 **이 입력으로 연구하기 →**를 누릅니다.

![식별된 Nicotinamide와 2D 분자 구조](docs/images/03-confirm-compound.jpg)

### 4. 짧은 첫 분석 선택 후 실행

첫 예제에서는 **입력 화합물만 평가**를 선택합니다. 모르는 피부 조건·제형·농도는 비워 두세요. 입력 물질 1개를 평가하며 새 후보를 찾지는 않습니다. 이후 DB 탐색을 하려면 **비슷한 화합물 찾기** 또는 **다른 골격 후보 찾기**를 선택합니다.

![입력 화합물만 평가 선택과 피부 조건](docs/images/04-analysis-options.jpg)

아래로 내려 계산 범위를 확인한 뒤 **새 연구 실행**을 **한 번** 누릅니다. 접수 중에는 버튼에 **연구 접수 중…**이 표시됩니다.

![계산 범위와 새 연구 실행 버튼](docs/images/05-run-study.jpg)

### 5. 진행 상태와 결과 확인

실행 버튼을 누르면 접수 중 표시가 바로 움직입니다. **파란 패널과 회전 표시**는 실행 대기·진행 중, **초록 패널과 체크 표시·연구 완료**는 처리가 끝났다는 뜻입니다. 상태는 5초마다 자동 확인합니다. 간단한 평가는 바로 완료될 수 있으며, 이 예제에서는 **입력 물질 1개·새 후보 탐색 요청 없음**으로 표시됩니다. 화면을 이동했으면 **내 연구 실행 기록 → 진행·결과 보기**로 돌아옵니다.

연결이 끊기거나 20초 동안 새 응답이 없으면 회전 표시가 멈추고 상태 미확인 안내가 나옵니다. **결과 갱신**으로 다시 확인하세요. 완료 표시는 계산 처리의 완료를 뜻하므로, 결과의 미평가·보류 항목도 확인합니다.

![Nicotinamide 평가 완료, 입력 물질 1개와 결과 버튼](docs/images/07-completed-study.jpg)

### 6. 구조·피부·독성 살펴보기

아래로 내려 **2D 구조**, 피부 특성과 **기존 DB 독성·ADMET 예측**을 확인합니다. 지표별 모델 출력·척도·버전을 함께 봅니다. 비어 있는 값은 미평가로 남습니다. 결합 구조의 리간드·수용체를 보려면 [3D 포켓 안내](docs/browser.ko.md#결합-구조-예제)를 따라 하세요.

![모델 버전·지표·단위가 함께 있는 ADMET 결과](docs/images/09-admet-results.jpg)

### 7. Excel 받기 — 두 번 클릭합니다

먼저 **Excel · 전체 후보·개별 물질 탭** 또는 실행 기록의 **Excel 받기**를 누릅니다. 준비가 끝나면 새로 나타난 **준비된 Excel 묶음 ZIP 저장** 링크를 누르세요. 첫 클릭은 파일 준비, 두 번째 클릭은 브라우저 다운로드 폴더에 저장입니다.

![Excel 준비 후 나타난 묶음 ZIP 저장 링크](docs/images/10-excel-ready.jpg)

ZIP 압축을 풀고 `review-0001.xlsx`를 엽니다. **후보 검토** 시트에서 시작해 `C000001` 같은 개별 화합물 탭으로 이동합니다. 연구를 공유할 때는 ZIP 전체를 보관하세요. 큰 연구는 여러 통합문서로 나뉘며 인덱스에서 연결됩니다.

후보 표에는 **SMILES 바로 앞에 2D 구조가 자동으로 포함**됩니다. 개별 화합물 탭에서도 같은 2D 구조와 원래 SMILES를 볼 수 있습니다. 저장된 도킹 포즈는 별도로 표시합니다. SMILES가 없거나 해석할 수 없으면 2D 그림 대신 그 이유를 표시합니다.

평가 점수·도킹 다음으로 피부 특성·구조 경보, 주요 독성 지표 6개, 수용해도·분자량·logP·TPSA·수소결합 수·QED를 열로 보여줍니다. 모델명·계산 상태·구매 정보도 함께 표시합니다. 복수 모델 값은 모델별로 구분하고, 결측과 유효 범위 오류를 표시합니다. 전체 ADMET 기록은 뒤쪽 원자료 열과 JSON에 보존됩니다.

브라우저 점수 헤더의 **?**에 마우스를 올리면 뜻·읽는 방향·비교 조건이 나옵니다. 키보드로 선택해도 열리며, 클릭으로 고정하고 Esc로 닫을 수 있습니다.

예측 결과에는 **분자 물성 6축**과 **독성 예측 6축** 레이더가 있습니다. 모델·출처별로 구분하고 원값·단위를 함께 표시합니다. 바깥쪽일수록 값이 크며 물성의 적정 범위는 연구 목적에 맞춰 봅니다. 미평가·품질 경고 항목은 비워 둡니다. **원값·단위·표시 범위**에서 숫자와 축을 확인하고, **그래프 SVG 저장**으로 그림을 받을 수 있습니다. 표시 범위는 점수나 필터를 바꾸지 않습니다.

반투명 **주황색 배경과 굵은 점선**은 현재 SkinPipe 피부 물성 점수에서 각 항목이 최고점인 범위입니다. logP 1–3.5, 분자량 350 g/mol 이하, TPSA 90 Å² 이하, 수소결합 공여체 3개 이하에 표시합니다. HBA·QED는 참고 범위 미설정입니다. 주황색 범례 옆 **?**에서 설명을 보고, 원값 표에서 참고 범위와 축 표시 범위를 구분해 확인하세요.

Excel 열 제목에 **↑ 높은 쪽 우선**, **↓ 낮은 쪽 우선**, **적정 범위·연구 목적에 따라 판단**을 표시합니다. **지표 읽는 법** 시트에서 단위·예시·비교 조건을 확인하세요. 도킹은 같은 계산 조건에서 더 음수인 값을 비교하며, 피부 투과·logP·분자 크기는 연구 목적과 함께 검토합니다. 개별 화합물 탭에도 각 값 옆에 읽는 방향을 표시합니다.

**초록색 연구 완료 표시와 다운로드한 Excel 열기까지 확인하면 첫 흐름을 마친 것입니다.** [그림으로 보는 전체 브라우저 안내](docs/browser.ko.md)에서 **SMILES·단백질·PDB/파일 입력**, 진행·취소·재개, 후보 비교, 2D/3D와 여러 연구 내보내기를 이어서 볼 수 있습니다.

## 다른 입력과 탐색 방식도 따라 하기

각 예제는 **다른 입력으로 새 연구**로 시작해 입력을 확인합니다. 결과가 나온 기존 연구는 보존됩니다. 짧은 첫 확인은 **후보 수·필터·최대 처리 시간 조정**에서 **대표 후보 목표 `2` · DB 평가 상한 `5` · 최대 시간 `0.1`시간**으로 설정할 수 있습니다. 이는 조작 확인용 한도이며 기본값 200개·1,000개·2시간이나 권장 연구 조건을 바꾸지 않습니다. 평가 전용에서는 후보 탐색을 하지 않습니다.

| 시작할 작업 | README에서 이어 할 동작 |
|---|---|
| SMILES 평가 | **화합물을 알고 있어요 → SMILES 분자 구조 (선택)**에 `NC(=O)c1cccnc1` 입력 → 2D·SMILES 확인 → **입력 화합물만 평가** |
| 유사 후보·다른 골격 비교 | `Nicotinamide` 또는 같은 SMILES 확인 → **비슷한 화합물 찾기** 또는 **다른 골격 후보 찾기**. 각각 별도 연구로 실행합니다. |
| 단백질 후보 | **단백질을 알고 있어요**에 `HSP90AA1` 입력 → 사람 / P07900 확인 → **이 단백질의 후보 찾기**. 작용 방향은 첫 화면의 **다른 종·작용 방향을 지정하려면**에서 **아직 정하지 않음 / 억제 후보 / 활성화 후보** 중 고른 뒤 다시 입력 확인합니다. |
| PDB 결합 구조 | **결합 구조가 있어요 → PDB ID → `1CBS`** → 모델 1·사슬 A·REA·잔기 200·조립체 확인 → **같은 단백질 포켓에서 다른 골격 후보 비교**. 파일은 **PDB/mmCIF 파일**에서 단백질과 리간드가 함께 있는 원본을 선택합니다. |
| 새 구조 생성도 비교 | 화합물의 유사·골격 탐색 또는 결합 구조 모드에서 **새 분자 구조도 만들어 비교하기 (선택)** → 생성 요청 체크. 처음은 BRICS 재조합 `2` · 3D 비교 `2` · 분자당 배치 `1`로 작게 확인할 수 있습니다. 치환 생성은 별도여서 전체 생성 수는 2개보다 많을 수 있습니다. 단백질·평가 전용 모드에는 이 선택이 없습니다. |

`1CBS` 파일 업로드에서 정확한 SMILES를 요구하면 [RCSB REA 원자료](https://files.rcsb.org/ligands/download/REA.cif)의 `SMILES_CANONICAL`(OpenEye OEToolkits 1.7.6)을 사용할 수 있습니다. **이 1CBS/REA 예제에만** 다음 값을 넣고 **선택한 결합 화합물 확인**을 누르세요. 사슬 A·REA·잔기 200과 단백질 사슬을 먼저 확인하며 다른 리간드에 재사용하지 않습니다.

```text
CC1=C(C(CCC1)(C)C)/C=C/C(=C/C=C/C(=C/C(=O)O)/C)/C
```

조건과 전달 범위를 확인하고 **새 연구 실행**을 한 번 누릅니다. 이후 위 5–7단계처럼 **진행·결과 보기 → 상태·미평가 확인 → Excel 준비 → ZIP 저장 → 통합문서 열기**까지 확인하세요. **초록 완료는 모든 지표 성공을 뜻하지 않으며**, 후보 0개·도킹 보류는 이유와 함께 읽습니다. 단백질의 요청 작용 방향은 활성화·억제 입증이 아닙니다. `1CBS`는 HSP90AA1의 도킹 구조로 넣지 않습니다. [모드별 상세 순서와 보류·0개 결과 읽기](docs/browser.ko.md#모드별-실행-예제)를 참고하세요.

## 다시 실행·종료·진행 확인

설치 후 다시 실행:

```sh
bash ~/SkinPipe/runtime/Start-SkinPipe.sh
```

다른 터미널에서 로컬 앱과 앱이 관리하는 작업 종료:

```sh
bash ~/SkinPipe/runtime/Stop-SkinPipe.sh
```

패키지·모델 환경 준비가 끝나 `Catalog-Status.sh`가 생성된 뒤 최초 DB 구축 진행 확인:

```sh
bash ~/SkinPipe/runtime/Catalog-Status.sh
```

`Prepare-Catalog.sh`를 포함한 실행 스크립트 생성이 모두 끝난 뒤 DB 구축이 중단됐다면 같은 설치 명령·옵션으로 재개합니다. 저장한 구축 기록을 이어 사용하며 두 번째 구축을 띄우지 않습니다. 그 전에 패키지 설치가 실패하면 로그를 보존하고 새 설치 폴더로 재시도하는 방법을 안내합니다. 준비 완료 후 앱을 다시 켜는 것만으로 전체 ADMET을 재계산하지 않습니다.

브라우저의 **설치 상태**에서 DB·인덱스·모델·도킹 엔진을 점검할 수 있습니다. [파일 위치와 문제 해결](docs/catalog.ko.md)도 참고하세요.

## ChatGPT 연결은 선택

기본 탐색·로컬 예측·결과·Excel은 ChatGPT 없이 동작합니다. **ChatGPT 연결 (선택)**에서 계정을 연결하고 **문헌 검토**에서 공개 문헌을 검토합니다. 입력 안내와 결과 설명에는 해당 연구에서 전달을 허용한 자료만 사용합니다.

모델 목록에 있으면 `gpt-6-luna` · `max`를 먼저 선택합니다. Luna가 없으면 제공자가 명시한 기본 모델을 사용하며, 기본 모델도 없으면 사용자가 목록에서 선택합니다. 호출 실패 후 다른 모델이나 별도 API 과금으로 자동 전환하지 않습니다. 사용할 수 있는 모델과 사용량은 연결한 계정에 따라 다릅니다. [연결·자료 전달 안내](docs/browser.ko.md#선택적-chatgpt-사용)를 확인하세요.

[2026-10-20 검증 기록](docs/validation-20261020.md)에 기존 누락 테스트, 공개 한 줄 명령 그대로의 새 Ubuntu 설치, 첫 연구·진행 확인·Excel 저장, 앱 재시작 후 결과 재열기와 검증 한계를 정리했습니다.

개발용 검사 명령과 기여 규칙은 [영문 README](README.md#development)와 [CONTRIBUTING.md](CONTRIBUTING.md)에 있습니다. SkinPipe 배포 라이선스는 추후 결정합니다. 포함된 외부 구성 요소는 각자의 고지를 유지합니다.

[2026-10-21 모드별 실사용 검증](docs/validation-modes-20261021.md): 단백질·PDB·파일·화합물 탐색과 실제 Excel 저장 범위·보류 사유를 확인하세요.
